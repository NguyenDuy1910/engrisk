## 0. Verdict

The design is **fit for Phase 1 implementation** with a small number of corrections. Its strongest parts are the single exam/attempt engine, disclosure-by-construction (separate `*Delivery` schemas), the change-set sync model for unreliable mobile sessions, and tenant isolation through the token plus 404 semantics. The main risks are not architectural but **contractual details that will bite during implementation**: a DBML check constraint that conflicts with pending AI evaluations, token-bearing responses in the idempotency store, the missing storage for the permission-version claim, the tutor's question-context disclosure rule, and P1 dependence on a table the DBML tags as P3 (`revision_audio_tracks`). Two issues found during review (verification-token expiry code, guest `set_goal`) were already resolved by integrator rulings A1 and A3 ([Integrator rulings](#integrator-rulings-a1a14)). Sections 6 and 8 list the findings; section 10 lists the decisions that need an owner.

**Update after integrator rulings A13–A14 ([Integrator rulings](#integrator-rulings-a1a14)):** the tutor question-context rule was adopted (A13) and M1, M3, M4, M5, M6 and M13 were added to the DBML gap list (A14). These findings stay listed in §6 with their status so the rationale remains traceable.

| Area | Assessment |

| Learning engine contracts | Strong. Server-authoritative time, per-change acks and section windows match the exam rules in product_flow §F. |

## 2. Rejected alternatives

| Alternative | Why rejected | When to revisit |
|---|---|---|
| **GraphQL** (single endpoint, client-shaped queries) | Disclosure rules are per-representation and per-attempt-state; field-level resolvers would scatter them and make "a delivery payload never contains an answer key" hard to prove. HTTP caching (ETag, `public` reference data), Problem Details, idempotency and presigned-upload flows are simpler in REST. The screens are known and few; consolidation already gives one call per screen. | If many new client surfaces (partner apps, analytics UI) need ad-hoc reads over published catalog data — as a read-only layer over `catalog`, never over attempts. |
| **Per-exam APIs** (`/toeic/part3/questions`, `/ielts/listening/get-audio`) | Duplicates the engine per exam and per Part; every new format becomes new routes, DTOs and client code. The DBML already models exam differences as data (`exam_revisions.sections`, `scoring_policy_key`). | Never for delivery. A format whose interaction model is genuinely different (e.g. live speaking with an examiner) would still be a new question `type`, not a new API. |
| **BFF per client** (web BFF, mobile BFF) | Two clients with the same data needs; generated TS clients already share types; a BFF doubles deployment and authorization surface. Screen-shaped aggregates that matter (`/me`, `/me/progress`, `getExam` viewer state) are in the core API. | If mobile needs aggressive payload trimming or offline sync bundles that web does not, or a third-party client appears. |
| **WebSockets** | No bidirectional real-time requirement: sync is client→server batches, server→client needs are job progress and tutor token streaming, both one-directional (SSE). WebSockets complicate auth refresh, load balancing and mobile backgrounding. | Live classrooms, proctoring, or collaborative editing in Studio. |
| **Generic CRUD over tables** (`/questions`, `/exam_revision_items`, `/attempt_responses` as raw resources) | Leaks storage shape, bypasses aggregate invariants (one draft per exam, cue invariants, immutability after publish), multiplies endpoints and makes authorization per table instead of per use case. | Never for public API; internal admin tooling can use SQL/read replicas. |
| **Revision-direct learner content access** (`GET /exams/{id}/revisions/{rid}/content` for learners) | Disclosure depends on attempt state (mode, checked positions, submitted, section windows); without an attempt the server cannot decide what to reveal or record what was served. Authors keep the revision preview endpoint with authoring permissions. | No. |
| **Header tenant context** (`X-Tenant-Id`) | Header is client-controlled and must be re-validated on every request; it invites confused-deputy bugs (e.g. worker or proxy forgetting to forward it) and cache-key mistakes. The session already carries `active_tenant_id`. | If one request must legitimately span tenants (platform staff tools) — via explicit platform endpoints, not a header. |
| **`ai_runs` as the public job resource** | One job may involve several provider calls (speaking = transcription + evaluation; multi-voice TTS) and retries; non-AI async work (normalization, account deletion, media processing) has no `ai_run`; exposing `ai_runs` leaks provider/model/prompt metadata and couples the contract to provider changes. | No; `ai_runs` stays an internal ledger. |
| **Per-response endpoints** (`PUT /attempts/{id}/responses/{position}`, annotation CRUD, check-answer endpoint) | N requests per page on flaky networks, no ordering across items, no batch ack, harder offline replay. The change-set makes retries idempotent by `seq` and keeps one aggregate write. | If a third-party integration needs single-answer writes — could be a thin alias mapping to a one-item change-set. |
| **Server-proxied media** (API streams uploads/downloads) | API instances would carry hundreds of MB per Listening track and 2 GB import packages; Range requests and resumable uploads would be re-implemented; costs CPU and egress on the API tier. | Only for tiny generated files if a client cannot reach storage (corporate proxies in P4). |
| **CDN presign on an R2 custom domain** | R2 presigned URLs work only on the S3 API endpoint; protecting a custom domain requires Cloudflare WAF token authentication (HMAC) — a paid-plan feature and a second signing scheme. P1 does not need edge caching for private media. | When learner audio latency or egress patterns justify it (§10 Q7). |
| **JSON Patch (RFC 6902) for attempts** | Index-based ops on arrays are fragile across devices; no per-op result; no ordering metadata. | No. |
| **Offset pagination with totals** | Unstable under inserts; `COUNT(*)` on large tables; not needed by any screen (Studio KPIs use `facets=status`). | Admin reports needing exact totals → dedicated report endpoints. |
| **Separate admin/Studio API namespace** (`/admin/exams`, `/studio/*`) | Duplicates resources and DTOs; authorization should be policy-based (permission keys), not URL-based. | No. |
| **Tenant in path** (`/tenants/{tenantId}/exams`) | Makes URLs tenant-specific and repeats the membership check per call; the token claim already scopes. `/tenants/current` covers admin needs. | Platform-staff cross-tenant tooling (P4+). |
| **Sparse fieldsets (`fields=`)** | Adds a combinatorial cache and authorization surface for little gain; payloads are already budgeted. | If mobile payload budgets are exceeded after `view`/`include` tuning. |

## 3. What the design gets right (keep)

- **Disclosure by schema, not by nulling.** `*Delivery` schemas physically lack protected properties; contract tests can assert it. This is the single most important safety property of the product.
- **Server-owned time** (`sections_state`, `paused_at`, sweeper, grace) — mock fairness and resume after app kill without trusting device clocks.
- **Idempotency only where repetition is harmful** (10 operations) and `seq`-based safety for the high-frequency sync path.
- **Copy-on-write versions exposed honestly** (`createQuestionVersion`, `createQuestionGroupVersion`, `409 question.immutable`, `question.grouped`) rather than hiding immutability behind silent clones.
- **Every non-created endpoint is a recorded decision** (api_contract "Endpoints deliberately not created"), which keeps future additions deliberate.

## 4. Over-engineering risks and what to defer

| Item | Risk | Recommendation |
|---|---|---|
| Multipart upload in P1 | Only staff need it in P1 (a 45-minute TOEIC Listening master as 48 kHz/24-bit WAV ≈ 390 MB; > 64 MiB threshold). Learners do not upload in P1. | Keep multipart for staff in P1 (the alternative — forcing compressed masters — conflicts with Studio QC rules), but implement resume (`uploadedParts`) only for `import_package` in P3. |
| Delivery variants / transcoding pipeline (`content_assets.variants`) | A transcoding worker is real work in P1. | Required: learners must never receive masters. Keep minimal — one AAC/M4A rendition per audio asset + duration probe; defer thumbnails and multiple bitrates. |
| SSE (`streamJobEvents`) | Holding long-lived connections on API workers; cross-instance fan-out. | Keep in P2 as tagged; P1 tutor uses polling. See §10 Q5. |
| `view=staff` provenance/usage on jobs | Minor surface with permission nuances. | Implement with `getJob` but return `provenance/usage` only to `content.author`; no separate admin UI in P1. |
| RLS | Two isolation mechanisms to test. | P4 as planned; P1 service predicates + composite FKs are enough while there is one tenant. Do add the `SET LOCAL` hook in P1 (zero cost) so P4 is a policy-only migration. |
| Rate-limit headers (IETF draft `RateLimit`/`RateLimit-Policy`) | Draft headers may change. | Emit `Retry-After` (stable) everywhere; draft headers optional. |
| `426 client_upgrade_required` | Needs a version matrix and ops process. | Implement the check in P1 (cheap) but keep the matrix empty until the first breaking need. |
| 8 question types in P1 | Essay/speaking scorers and evaluation pipelines are P2; matching/ordering are IELTS-only. | Ship all 8 *schemas* in the contract (stable union) but only the objective scorers needed for TOEIC L&R + IELTS Reading/Listening in P1. |
| Cross-device last-write-wins | Simple, but "arrival order" across devices can surprise. | Keep; document in client SDK; no vector clocks. |
| `exam_stats` materialization | Ratings arrive only in P3. | P1: play/completed counts only (catalog "lượt làm"); add rating columns in P3. |
| Audio-track authoring endpoints in P1 (ops 37–39) | Needed only if a full TOEIC mock with a continuous Listening track ships in P1. | Keep if full mock is in P1 scope (product says yes); otherwise defer with `revision_audio_tracks` (§6 M4). |
| Jobs in the `ai` module | Non-AI jobs (account deletion, media processing, import validation) live in a module named `ai`. | Acceptable for P1; if non-AI job types grow, move the job runtime to `platform` and keep `ai` for providers + tutor (no contract change). |

## 5. Consolidation opportunities still open

| Opportunity | Current design | Option | Recommendation |

## 7. Performance risks

| Risk | Where | Why it matters | Mitigation |
|---|---|---|---|
| Sync write amplification | `PATCH /attempts/{attemptId}` every ~600 ms per active learner | Each flush updates several `attempt_responses` rows (+ `attempts.last_activity_at`); MVCC churn and autovacuum pressure on the hottest table. | Coalesce per position client-side; only update changed columns; keep `attempt_responses` fill factor < 100 to favor HOT updates; update `last_activity_at` at most once per N seconds. |
| Submit transaction | `POST /attempts/{attemptId}/submit` (200 items) | Grading + `attempt_scores` + `learner_skill_stats` upserts in one transaction; contention on skill stats rows for the same user is low, but the ≤ 200 ms target needs bulk SQL. | Grade in memory from the cached projection; single bulk `UPDATE … FROM (VALUES …)`; skill-stat upserts batched; evaluations enqueued via job rows in the same transaction. |
| Dashboard aggregate | `GET /me/progress` | Sum of 6–8 queries; called on every Home open. | ETag on a cheap version key (max of attempt/goal/stats `updated_at`) → 304 most of the time; bounded windows; precompute daily KPIs only if p95 > 50 ms. |
| Projection cache memory | in-process cache of revision projections × sections × views × instances | Large mocks (200 items with passages) multiply by instances. | LRU with byte cap; cache only published revisions; Redis shared cache when instances > 2 (architecture §8.7). |
| Long-lived signed audio for mocks without CDN | Learners in Vietnam fetching 30–40 MB section audio from the R2 S3 endpoint | Start latency and buffering in mock Listening, where pausing is not allowed. | Deliver AAC variants (~96 kbps); range requests; measure TTFB from VN in P1 beta; trigger for custom-domain CDN decision (§10 Q7). |
| Deadline sweeper and queue polling | Worker loops every 15 s; SKIP LOCKED polling | Polling cost grows with worker count. | Partial indexes (`ix_attempts_deadline_sweep`, jobs queue index); `LISTEN/NOTIFY` wake-ups to lengthen poll intervals. |
| SSE connections (P2) | `GET /jobs/{jobId}/events` | Each tutor stream holds a connection on an API worker. | Async server, connection caps, heartbeat 15 s, close after terminal event; polling fallback always works. |
| Media authorization lookups | `GET /media-assets/{assetId}` for question media | Reverse lookup through revisions (M24). | Resolve through the attempt's cached projection asset set; index fallback. |
| Reference-data growth | `GET /reference-data` | Skills taxonomy and templates grow with new exam types. | Budget 30 KB gzip; split authoring parts behind `include=`. |
| AI cost spikes | tutor, evaluations, generation | Cost, not latency, is the scaling limit. | Entitlement limits, per-user daily quotas, interactive vs bulk pools, `ai_runs.usage` monitoring. |

## 8. Security risks

| Risk | Scenario | Impact | Mitigation in design | Residual / action |
|---|---|---|---|---|
| **Signed URL bearer leakage** | A learner shares a signed mock-track or recording URL; URLs end up in logs, crash reports or browser history. | Anyone with the URL can fetch until expiry; mock track TTL = section window + 10 min (~55 min for TOEIC Listening). | Short TTLs per purpose (recording 5 min, practice 30 min, authoring 15 min); unguessable keys; private bucket with no listing; revocation by deleting/rotating the object; never log query strings; `Referrer-Policy: no-referrer`. | Accept for P1; revisit with edge token auth (§10 Q3, Q7). |
| **Client-side replay limits, no DRM** | Mock "no replay/no seek" is enforced by the player; the learner can download the track from its URL and replay it. | Mock realism, not data confidentiality: the transcript and answer keys are still withheld. | Server-side windows prevent late answers; transcript/cues withheld in delivery. | Document to stakeholders: Engrisk is a practice product, not a proctored exam. |
| **Answer-key oracles** | (a) Tutor `question` context (M18). (b) Practice `check:true` reveals keys for any practice-mode exam; a learner could practice-check a set and then take it in mock. | Harvesting verified keys/explanations (the core content asset). | Disclosure table; `full_mock` exams are mock-only (DBML `exam_kind` note); tutor `question` context limited to disclosed questions (A13). | Decide Q13 (practice on `full_mock`); rate-limit attempt starts per user. |
| **Guest abuse** | Scripts create guest sessions and attempts to scrape guest-tier content and keys via `check:true`; DB bloat. | Content scraping, cost. | `Idempotency-Key` on guest creation; guest tier limited to small sets; cleanup job. | Add bot protection (e.g. Cloudflare Turnstile) on guest creation and per-IP limits on `POST /auth/sessions` and `POST /attempts`. |
| **Idempotency store contents** | Responses replayed from `idempotency_keys.response_body` contain tokens (M3) or learner data. | A DB read compromise exposes refresh tokens; cross-user replay if keys are not scoped. | Keys scoped per user + method + path with request hash. | Never store secrets; re-issue on replay; 24 h purge; exclude token-bearing bodies. |
| **JWT tenant/permission staleness** | A teacher removed from a tenant keeps a valid 15-minute access token. | Up to 15 min of continued access. | `ver` claim and principal cache. | Check the current version per request (cached ≤ 30 s) rather than trusting `ver` blindly; revoke sessions on membership suspension; requires M5. |
| **SVG branding** | Tenant logo SVG with script or external references served from a public URL. | Stored XSS if rendered same-origin or opened directly. | "SVG (sanitized)" in purposes. | Serve public assets from a separate cookieless domain with `Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'`, `X-Content-Type-Options: nosniff`; or rasterize SVG to PNG at processing time (preferred). |
| **Zip bombs and malicious packages** | 2 GB import ZIP with extreme compression ratio, path traversal names, XLSX with external entities, CSV formulas in the downloadable report. | Worker DoS, file overwrite, XXE, spreadsheet formula injection for staff. | Import validation runs in the worker; packages are private. | Enforce limits on entry count, total uncompressed size and ratio; reject absolute/`..` paths; parse XLSX with a hardened parser (no external entities); prefix formula-leading cells in CSV reports; malware scan before validation. |
| **Prompt injection via uploaded materials and community content** | Source material or a contributed passage contains instructions to the generation or tutor model. | Generated drafts with wrong keys or unsafe text; tutor revealing more than allowed. | Generated items are private drafts requiring human review; tutor context assembled server-side from disclosed data only; no side-effecting tools. | Delimit untrusted text, validate model output against Pydantic schemas, run `quality_check` and safety checks before any publish; keep tutor grounding limited to disclosed fields. |
| **Timing manipulation** | Device clock changes; offline after deadline; inflated `timeSpentMsDelta`; repeated practice pause. | Unfair mock results; skewed analytics. | Server-authoritative deadlines and section windows; changes after deadline + 30 s grace rejected per change; mock has no pause. | Cap `timeSpentMsDelta` by wall-clock since last applied change; practice pause abuse only affects the learner. |
| **Account enumeration** | `addIdentity` returns `identity.email_taken`; sign-in errors. | Email existence disclosure. | Verification-token requests always 202; generic `auth.invalid_credentials`. | Rate-limit `addIdentity` and sign-in per IP/user; accepted residual for `email_taken`. |
| **Upload type spoofing** | A file declared `audio/mp4` is something else. | Malicious content stored and served. | Allow-list per purpose; checksum + size verification on complete; scan/probe in `processing`. | Verify magic bytes during processing; force `Content-Type` and `Content-Disposition` on signed GETs. |
| **Teacher access to learner data (P4)** | `evaluation.review` / `learner_progress.read` misuse. | Privacy breach. | Explicit permissions, same-tenant only, never tutor content. | Audit log for every staff read of learner-private data (`platform.support.read` too). |
